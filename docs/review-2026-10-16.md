# Repo review, 2026-10-16

Scope: whole repo at `9ba427f` (0.1.8), except `src/main.rs` and `src/details.rs` (UI), which were not read in full. Tests were not run. Assumed load: one person, one game running at a time.

Verdict: fix 1, 2 and 3 first.

## Must fix

### 1. A failed extraction leaves a half-extracted game that looks ready
`src/extract.rs:L249-262`, `L325-373`

Only `Cancelled` triggers `created.roll_back()`. Any other error (disk full, corrupt stream, permission, file/folder clash) leaves the written files. `status()` then sees non-zip files beside the zip and reports `Ready { has_zip: true }`, so the game looks playable and is never offered for extraction again.

Fix: roll back on any `Err`: `if result.is_err() { created.roll_back(); }`. Add the test from 6.

### 2. A cut-off write can wipe a game's profile and block launching
`src/profile.rs:L209-214`

`std::fs::write` truncates, then writes. A crash in between leaves a short or empty `profile.json`. `read_profile` returns `InvalidData`, and `Launcher::start` fails on `read_tuning(game_dir)?` until the user deletes `.dackel/profile.json`.

Fix: write `profile.json.tmp` in the same folder, then `fs::rename`. Same for `src/settings.rs:L61`.

### 3. Steam's `shortcuts.vdf` is overwritten in place
`src/steam.rs:L432-443`

Same truncate-then-write. A cut-off write loses every non-Steam shortcut the user has. The backup is made once and never refreshed.

Fix: temp file and rename. Keep the one-time backup.

## Should fix

### 4. Two writers can lose each other's profile change
`src/winetricks.rs:L96-98`, `src/launch.rs:L296`

Every profile change is read-modify-write with no lock. A long winetricks install ending at the same time as a game exit can drop `add_winetricks` or `add_play_time`.

Fix: do not allow launching a game while its winetricks install runs (one UI flag). A file lock is more than this app needs.

### 5. Play time is lost if the profile write fails; one bad profile blocks other launches
`src/launch.rs:L296-308`

`poll` removes the finished session before `add_play_time` succeeds. `start` calls `self.poll(now)?`, so a failed write for game A aborts launching game B.

Fix: in `start`, report the `poll` error and continue.

### 6. No test for cleanup after a write error
`tests/extract.rs`, `tests/extract_job.rs`

Add one test: a zip whose later entry fails to write (a directory already sits where a file must go). Assert the folder holds only the zip afterwards.

### 7. Stray doc comment on the wrong item
`src/extract.rs:L172-174`

"Extracts every zip directly in `game_dir`... leaves the folder untouched" sits above `Progress`, and is false today (see 1). Delete it, or move it to `extract_with_existing` after fixing 1.

## Nice to have

### 8. A user's `WINEDLLOVERRIDES` removes the Wayland-off default
`src/launch.rs:L48-52`, `L58-64`

User env is applied over the default `winewayland.drv=d`, so setting their own overrides silently brings back the OpenGL failure. Append the user's value with `;`, or note it in the Env help text.

### 9. Install checksums come from the same place as the files
`scripts/install.sh:L53-59`

`SHA256SUMS` catches a broken download, not a replaced release. Not a bug; just do not present it as a security check. Sign releases or pin a hash if that matters later.
